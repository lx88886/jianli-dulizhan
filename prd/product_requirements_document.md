# 仓库展示与预定系统 - 产品需求文档 (PRD)

## 1. 项目概述
### 1.1 背景
本项目原为一个标准的电商小程序（商城），现需转型为一个**仓库展示与商品预定系统**。
核心目标是弱化“购物”属性，强化“展示”与“预定”属性。用户主要用于浏览仓库库存，提交预定意向，而非直接进行在线支付和购买。

### 1.2 目标
- **去电商化**：移除在线支付、复杂的营销工具（优惠券、秒杀等）、发票管理等功能。
- **强化展示**：清晰展示商品库存、规格。
- **流程重构**：将“购物车 -> 结算 -> 支付”流程改造为“预定单 -> 提交预定 -> 等待确认”。

## 2. 用户角色
- **普通用户（浏览者/预定者）**：浏览商品，查看库存，提交预定申请。

## 3. 功能模块规划与改造

### 3.1 首页 (Home)
- **现状**：电商风格，包含轮播图、热门推荐、促销活动等。
- **改造需求**：
    - **保留**：轮播图（展示仓库环境或新品）、商品列表（展示热门/推荐库存）。
    - **移除**：营销类入口（如领券中心、秒杀专区）。
    - **新增/调整**：
        - 顶部可增加仓库选择（如果有多仓库）。
        - 列表项重点展示“库存数量”。

### 3.2 商品分类 (Category)
- **现状**：左侧导航，右侧商品列表。
- **改造需求**：
    - 基本保持不变。
    - 列表项需突出“规格”和“当前库存”。

### 3.3 商品详情 (Goods Detail)
- **现状**：包含价格、销量、评价、加入购物车、立即购买。
- **改造需求**：
    - **文案修改**：
        - “价格” -> 可保留，或改为“参考价/单价”。
        - “销量” -> 建议改为“已预定”或直接隐藏。
        - “加入购物车” -> 改为 **“加入预定单”**。
        - “立即购买” -> 改为 **“立即预定”**。
    - **功能调整**：
        - 移除评价模块（可选，视需求而定，仓库系统通常不需要评价）。
        - 移除“分销/分享赚”等营销功能。
        - 重点展示：**库存余量**、商品参数。

### 3.4 预定单 (原购物车 - Cart)
- **现状**：购物车逻辑，包含选中、计算总价、促销计算。
- **改造需求**：
    - **名称变更**：**“预定清单”**。
    - **功能调整**：
        - 移除价格计算中的“优惠”部分。
        - 底部结算栏：
            - “合计”金额可以保留作为参考，也可以隐藏（取决于是否需要让用户知道总价值）。
            - 按钮由“去结算”改为 **“填写预定信息”**。

### 3.5 预定确认 (原订单确认 - Order Confirm)
- **现状**：选择地址、选择优惠券、选择发票、计算运费、微信支付。
- **改造需求**：
    - **核心变更**：这是改动最大的页面。
    - **保留**：
        - 商品清单确认。
        - 备注信息（用户填写特殊需求）。
    - **修改**：
        - “收货地址” -> 改为 **“联系信息确认”**（姓名、电话、提货方式/配送地址）。
        - 提交按钮 -> **“提交预定申请”**。
    - **移除**：
        - **微信支付/在线支付功能**（彻底移除）。
        - 优惠券选择。
        - 发票信息。
        - 运费计算（除非预定也需要计算运费，否则建议移除或改为线下确认）。

### 3.6 个人中心 (User Center)
- **现状**：包含订单管理（待付款、待发货...）、优惠券、收货地址等。
- **改造需求**：
    - **订单管理** -> 改为 **“预定记录”**。
    - **状态流转**：
        - 原：待付款 -> 待发货 -> 待收货 -> 完成
        - 新：**已提交** -> **已确认** (管理员确认) -> **已完成** (已提货/发货) / **已取消**。
    - **移除**：
        - 待付款入口。
        - 评价中心。
        - 退款/售后（预定阶段通常不涉及复杂的线上售后，可简化为电话联系）。

## 4. 详细页面变更清单

| 页面 | 现有功能 | 变更后功能 | 备注 |
| :--- | :--- | :--- | :--- |
| **通用** | 底部导航栏 | 首页、分类、预定单、我的 | 图标和文案需更新 |
| **商品详情** | 价格、销量、评价、促销 | 库存、规格、参考价 | 弱化营销，强调库存 |
| **底部操作栏** | 客服、购物车、加入购物车、购买 | 客服、预定单、加入预定单、立即预定 | |
| **购物车** | 选中、数量、总价、优惠 | 选中、数量、(参考总价) | 去除优惠逻辑 |
| **结算页** | 地址、优惠券、发票、支付 | 联系人、预定时间、备注、提交 | **移除支付接口** |
| **订单列表** | 待付款、待发货... | 待确认、已确认、历史预定 | 状态机重构 |

## 5. 技术实现注意点
1.  **支付拦截**：确保所有涉及 `wx.requestPayment` 的代码都被移除或注释。
2.  **接口调整**：
    - 提交订单接口需调整为“创建预定单”，不再返回支付参数，而是直接返回预定成功状态。
    - 订单列表接口需映射新的状态值。
3.  **UI 调整**：全局搜索“购买”、“下单”、“支付”、“优惠”等关键词，进行文案替换。

## 6. 后续规划
- 增加管理员端（或小程序内增加管理员权限），用于审核/确认用户的预定单。
- 增加库存预警功能。
